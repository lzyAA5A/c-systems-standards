# 自审清单、审阅顺序与危险模式检索

> 用法：写完 C 代码（或收到一份 C 代码要审）后，按 §2 的顺序过一遍，用 §1 的清单做记录。
> 清单里 **F = 致命（必须改）**，**I = 重要（本次改）**，**S = 建议（记录即可）**。

## 1. 30 项自审清单

### 输入与边界（最容易出事）

- [ ] **F** 每个公开函数对 `NULL` 指针 / 0 长度 / 超长输入都有明确行为
- [ ] **F** 所有接收缓冲区的写入都有长度上限，且 `cap == 0` 被拒
- [ ] **F** 数组下标与长度运算没有 off-by-one（`<=` vs `<`、`len - 1` 当 `len == 0`）
- [ ] **I** 外部输入（文件/网络/argv/环境变量）在被信任前校验了范围与编码
- [ ] **I** 协议/文件里的长度字段在分配内存**之前**做了上限检查

### 内存

- [ ] **F** 每条 `malloc/calloc/realloc/strdup` 都有对应的释放路径（含错误路径）
- [ ] **F** `realloc` 用临时变量接收，失败不丢原指针
- [ ] **F** 所有权（拥有/借用/接管）在头文件里写明，跨模块传递时不产生双重释放
- [ ] **F** 释放后指针置 NULL（可写变量）
- [ ] **I** 结构体里的"拥有指针"在 `_destroy()` 里统一释放
- [ ] **I** 没有 `alloca`、没有变长数组（`-Wvla` 已拦）

### 整数与运算

- [ ] **F** 长度/下标是 `size_t`，没有 `int` 与 `size_t` 混算
- [ ] **F** 乘法/加法导致的溢出有检查（尤其 `n * sizeof(T)`）
- [ ] **F** 移位量小于类型宽度，左移对象无符号
- [ ] **I** 减法的下溢有前判断（`if (n > 0)`）
- [ ] **I** 有符号/无符号比较没有触发隐式转换（`-Wsign-compare` 干净）
- [ ] **S** 用定宽类型的地方（协议/文件/哈希）都显式用了 `uint32_t` 等

### 返回值与错误

- [ ] **F** 所有可能失败的调用都检查了返回值（含 `close`/`fflush`）
- [ ] **F** 错误码能区分"失败"和"截断/部分成功"
- [ ] **F** `errno` 在调用后立刻取，不跨调用使用
- [ ] **I** 失败路径有可定位日志（函数名 + 关键参数 + 错误码）
- [ ] **I** 没有用 `assert` 做参数校验（Release 会消失）
- [ ] **S** 每个错误码都有调用方动作（重试/上报/退出）

### 资源与并发

- [ ] **F** 每对获取/释放（fd、FILE、HANDLE、锁、socket、映射）都配平，含错误路径
- [ ] **F** 单一出口清理（`goto cleanup`），没有中途裸 `return` 漏释放
- [ ] **I** 头文件标明了线程安全性（安全 / 需外部加锁 / 单线程）
- [ ] **I** 共享状态有锁或原子；锁的获取顺序全局一致
- [ ] **I** 没有可重入性问题（`strtok`、`localtime`、`strerror`、静态缓冲返回值）

### 平台与构建

- [ ] **F** `#ifdef _WIN32` 只出现在 `os_*.c` 适配层
- [ ] **F** 文件 I/O 显式 `"rb"/"wb"`；文本处理显式处理 `\r\n`
- [ ] **I** 64 位量用定宽类型与 `PRI*` 格式，没有 `long`/`%ld`
- [ ] **I** 路径拼接不硬编码分隔符；Windows 编码转换集中一处
- [ ] **S** 导出的结构体有 `_Static_assert(sizeof/offsetof)`

### 可读性（不改也能跑，但会拖累维护）

- [ ] **S** 函数 ≤ 60 行、嵌套 ≤ 3 层、参数 ≤ 5 个
- [ ] **S** 命名符合模块前缀约定；没有 `data`/`tmp`/`handle` 这类无信息名
- [ ] **S** 注释写"为什么/契约"，不是复述代码

## 2. 审一坨 C 代码的固定顺序（7 步，别跳）

1. **读契约**：头文件 → 每个函数的输入/输出/所有权/错误码。
2. **只看输入边界**：所有外部数据从哪里进来？每个入口的长度、编码、上限谁管？
3. **走内存路径**：从分配到释放画一条线，把错误分支也画上。找到"分配后中途返回"的点。
4. **走错误路径**：把每个 `if (rc != 0)`/`goto cleanup` 单独当主流程读一遍——错误路径里的错误最常见（忘关、忘置 NULL、返回了未初始化的 out 参数）。
5. **查整数**：所有 `*`、`+`、`-`、`<<`、`[i]` 的边界。
6. **查并发**：谁写这块内存？锁保护的是不是同一个对象？有没有"检查后使用"的间隙（TOCTOU）？
7. **查平台假设**：`long`、路径、编码、`sizeof`、`#ifdef`、系统调用语义。

每步发现的疑点先记下来（文件:行 + 一句话），最后统一判定严重度——不要在第一步就动手改。

## 3. 危险模式检索（本机用 grep 工具，不要用 shell grep）

按优先级跑这些检索，命中即人工确认：

```
\b(strcpy|strcat|sprintf|vsprintf|gets|alloca|system|popen|mktemp|tmpnam|rand)\s*\(
```
```
\b(malloc|calloc|realloc)\s*\([^)]*\)\s*;      # 分配结果被丢弃
```
```
\b(realloc)\s*\(\s*(\w+)\s*,                  # 可能是 p = realloc(p, ...)
```
```
[fF]ree\s*\(.*\)\s*;(?!.*=\s*NULL)            # 释放后未置空（需看上下文）
```
```
sizeof\s*\(\s*(char|void)\s*\*            # sizeof(指针) 当 sizeof(数组) 用
```
```
\bint\s+\w*\s*=\s*\w*len|\bint\s+\w*\s*=\s*strlen
```
```
%\s*(d|u|ld|lu)\b                             # 打印 64 位量的可疑格式
```
```
\bfopen\s*\([^,]+,\s*"[^"]*"                  # 检查是否漏 "b"
```
```
#\s*if(def)?\s+_WIN32                          # 是否出现在适配层之外
```
```
fopen|open\s*\(                              # 逐个核对返回值与 close
```
```
\b(verify|wcscpy|wcscat|lstrcpy)\b             # Windows 宽字符的无界函数
```
```
TODO|FIXME|XXX|HACK                           # 遗留标记是否阻塞发布
```

再补一轮"返回值被忽略"的检查：所有 `read|write|fread|fwrite|fclose|close|CloseHandle|send|recv` 调用前后，看返回值有没有被检查。

## 5. 审阅报告的格式（给人和给模型都用）

```
严重度清单
  F-1 src/buf.c:118  越界写：cap 判断用了 <= ，off-by-one
  F-2 src/net.c:240  recv 返回值未判部分读 → 数据截断
  I-1 src/os.c:66    线程安全未声明，被两个线程调用
  S-1 src/buf.c:30   函数 92 行，建议抽 buf_grow_steps

验证情况
  已跑：check-c.ps1 (gcc, 0 warning)、check-c.ps1 -Analyzer（无告警）
  未验证：Windows 侧行为（无 Windows CI）、大文件（>2GB）路径
```

要点：**每条都要带 文件:行 + 一句话结论 + 为什么**；没有验证过的结论必须说明"未验证"，不要把"读起来没问题"写成"已验证"。

## 6. 常见"看着没问题"的错觉（复审时重点怀疑）

- "这个函数只会传合法的参数"——调用点会变。
- "这里不会失败"——磁盘满/权限/OOM 都会失败。
- "这是内部函数"——半年后它会被导出。
- "编译器会优化掉"——UB 下它可以优化成任何东西。
- "Linux 上跑了一百遍"——Windows 上的 `long`、CRLF、路径编码一个都没测。
- "警告不影响运行"——今天不影响，明天换个编译器就会变成错误行为。
